NANOSEAL ONLINE — ВЕРСИЯ ДЛЯ ИНТЕРНЕТА

Что изменилось:
- Сайт и панель производителя работают по обычной HTTPS-ссылке.
- Python, локальный сервер и start_windows.bat больше не нужны.
- Коды, статусы и статистика хранятся в Cloudflare D1.
- Подпись ECDSA P-256 создаётся и проверяется на сервере Cloudflare.
- QR-коды скачиваются в SVG: векторный формат подходит для печати.
- Панель производителя защищена паролем.

ВАЖНО: Архив — готовый проект для публикации, а не уже опубликованный сайт.
Чтобы получить ссылку вида https://nanoseal-online.<ваш-аккаунт>.workers.dev,
нужно один раз разместить проект в собственном аккаунте Cloudflare.
Без доступа к вашему аккаунту публикацию выполнить нельзя.

КАК ОПУБЛИКОВАТЬ (ОДИН РАЗ, НА КОМПЬЮТЕРЕ АВТОРА САЙТА)

1. Зарегистрируйте аккаунт на https://dash.cloudflare.com/ .
2. Для публикации установите Node.js (только автору сайта, НЕ посетителям).
3. Распакуйте архив и откройте терминал в папке NanoSeal_Online.
4. Выполните:
      npm install
      npx wrangler login
      npx wrangler d1 create nanoseal-online-db
   Скопируйте database_id из результата.
5. Откройте wrangler.jsonc и замените REPLACE_WITH_DATABASE_ID на полученный ID.
6. Создайте таблицы:
      npx wrangler d1 execute nanoseal-online-db --remote --file=schema.sql
7. Установите секретный пароль панели производителя:
      npx wrangler secret put ADMIN_PASSWORD
   Введите сложный пароль (он не сохраняется в файлах проекта).
8. Опубликуйте:
      npm run deploy
   Wrangler покажет HTTPS-ссылку вида https://nanoseal-online.<subdomain>.workers.dev.

Теперь пользователи открывают эту ссылку на любом устройстве без установки ПО.
Панель производителя: <адрес-сайта>/admin.html
Имя пользователя для панели: nanoseal
Пароль: тот, который был введён на шаге 7.

ПРОВЕРКА ПОСЛЕ ПУБЛИКАЦИИ
1. Откройте главную страницу, нажмите «Настоящий код» — должна появиться подтверждённая подпись.
2. Нажмите «Изменённый код» — должна появиться ошибка подписи.
3. Нажмите «Отозванный код» — должен появиться статус отзыва.
4. В панели производителя выпустите товар, скачайте SVG с QR-кодом.
5. Отсканируйте QR телефоном: он должен открыть вашу опубликованную страницу проверки.
6. Отзовите код и повторите проверку: статус должен измениться.

ОГРАНИЧЕНИЯ И БЕЗОПАСНОСТЬ
- Публичный QR-код можно скопировать. Дополнительно проверяйте физическую голограмму.
- Вход в панель реализован через HTTP Basic Authentication. Для коммерческой эксплуатации
  нужны полноценные аккаунты, MFA, разграничение прав и аудит.
- Закрытый ключ подписи хранится в D1 (защищён доступом к аккаунту Cloudflare),
  а не в HSM. Для промышленной системы требуется отдельное управление ключами.
- Новая облачная база создаётся пустой. Старые QR-коды из локальной версии
  НЕ будут действительны: в новом проекте создаётся новая пара ключей.
- Тарифы Cloudflare и лимиты бесплатного использования могут изменяться.

Если нужно опубликовать без установки Node.js даже у автора, можно загрузить проект
в GitHub и настроить Cloudflare Workers Builds, но привязка D1 и секрет ADMIN_PASSWORD
всё равно выполняется в аккаунте Cloudflare.
